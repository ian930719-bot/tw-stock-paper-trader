# 台股 AI 模擬交易研究系統

本專案供研究與模擬交易使用，不連接券商、不送出真實委託，也不構成投資建議。

## 部署與執行

本專案部署於 Streamlit Community Cloud；`main` 分支更新後會觸發重新部署。

本機執行：
```bash
pip install -r requirements.txt
streamlit run app.py
```

## 目前功能

- 自動交易模擬引擎：只對 AI 多因子觀察訊號且取得盤中更新報價的標的建立限價模擬委託；買進依 ATR 距離估算股數、賣出依 EMA21／RSI／MACD 退出條件產生訊號，並設單筆金額、單一標的曝險、總曝險、每日虧損（無法核對成本時會鎖定委託）、未完成委託數及每日委託數上限；具防重複委託識別碼、等待委託取消及 SQLite 委託紀錄。預設關閉，需手動啟用本輪模擬。
- 模擬委託撮合只有在輸入市場價格觸及限價時才標記成交；此為測試用撮合，不代表真實市場成交機率或完整撮合隊列。

- 全市場上市／上櫃證券主檔：透過 FinMind TaiwanStockInfo 每日更新資料，保留每個代號最新市場別，涵蓋上市、上櫃股票及 ETF 等數字／英數代號證券；支援市場、產業、代號與名稱搜尋及完整 CSV 匯出。
- 觀察清單可直接從完整主檔搜尋選取；為控制行情來源限流，單次技術行情載入上限 30 檔，預設載入常用觀察標的。
- 主檔 API 失敗時會明確標示並切換內建備援名單，不會把備援清單冒充完整資料庫。
- EMA、RSI、MACD、OBV、ATR、20／60 日報酬與量價突破指標。
- 隨機森林預測未來 5 個交易日報酬是否超過 1.5%；採時間順序測試，對五日標籤重疊做 purge，並與多數類基準模型比較平衡準確率。最新預測模型使用全部已標記資料重新訓練；輸出機率尚未校準。
- 三種技術策略代理：Minervini 趨勢模板、O’Neil CAN SLIM 技術代理、Livermore 順勢突破。
- 多股票共享現金回測：持倉上限、動能排序、可調單筆風險預算、ATR 停損與成本估算；各標的若資料提早終止，會在該標的最後可用收盤日平倉。
- 回測風險指標：年化波動率、Sharpe、Sortino、Calmar、最大回撤與平均曝險。
- 成交統計：勝率、平均獲利、平均虧損、Profit Factor、單筆期望值與平均持有日數。
- 模擬帳本顯示持倉資產占比，單一持倉達總資產 50% 時提示集中風險。
- 訓練／驗證／樣本外切分：使用共同交易日期，保留區段前資料暖機，績效只從區段起始日計算。
- 市場基準比較：以 0050 還原價格及加權指數價格指數，對齊完整歷史或樣本外區間。
- 成本敏感度：固定手續費與一般股票賣出稅，測試單邊滑價 0.1%、0.2%、0.3% 對策略結果的影響。
- 最新基本面快照與巴菲特／彼得林區風格簡化條件檢查。
- 行情資料品質檢查：日期間隔、缺漏列、非正價格與資料新鮮度。
- 盤中報價狀態：區分盤中更新、盤中延遲／可能休市、當日最後報價、非當日報價與無報價；非盤中時段不會把當日收盤價誤標成即時行情。
- 模擬帳本買賣、CSV 成交紀錄、JSON 備份與還原。
- GitHub Actions 語法檢查及研究引擎單元測試。

## 重要資料與模型限制

- 歷史日線優先使用 FinMind TaiwanStockPriceAdj，透過 SQLite 對已選取標的做增量更新（重疊最近 10 個日曆日以接收修訂）；首次無 FinMind 資料時才使用 Yahoo Finance 自動還原日線備援。盤中參考行情仍使用 Yahoo Finance，可能延遲、修訂或缺漏，並非交易所認證資料。
- 三種技術策略是依公開理念建立的量化代理，不代表完整複製投資大師的方法。
- 巴菲特／林區目前只有最新財務快照的簡化條件檢查，並非 point-in-time 歷史財報，也不可用來宣稱歷史回測績效。
- 現行上市／上櫃主檔由 FinMind TaiwanStockInfo 提供，依同一代號最新 date 判斷轉板後的現行市場別；不包含興櫃、權證、歷史下市證券，也不等於歷史成分股資料庫。資料服務中斷時會顯示內建備援名單並警告，不會宣稱全市場完整。
- 全市場主檔每 6 小時於應用程式快取更新；行情載入仍限制 30 檔，避免一次對所有股票逐檔呼叫行情服務。FinMind 免費 API 有每小時請求上限，故不會對 2,712 檔全市場同時逐檔抓取。SQLite 僅快取使用者選取的標的，預設存放執行環境暫存目錄；Streamlit Community Cloud 重啟／重新部署可能清除，並非永久資料庫。可透過 `MARKET_DB_PATH` 指定本機資料庫路徑；若要雲端永久保存，仍需外部資料庫及連線憑證。
- 回測成交以訊號日收盤後的資訊，於下一交易日開盤執行。日線無法精確還原盤中成交先後。
- 基準比較使用 Yahoo Finance 的 0050 還原價格與加權指數價格指數；基準曲線未扣成本，指數不含股息，0050 仍有追蹤誤差與 ETF 費用。
- 成本估算為手續費 0.1425%、一般股票賣出證交稅 0.3%、單邊滑價 0.1%；敏感度測試將單邊滑價提高至 0.2% 與 0.3%，仍未涵蓋個別券商折扣、最低手續費、ETF 稅率及市場衝擊。
- 單筆風險預算是依進場價至 ATR 停損價的距離估算，不是最大損失保證；跳空、漲跌停及流動性不足可能使實際損失超過預算。
- 尚未完整處理除權息現金流、停牌、漲跌停排隊、流動性衝擊與歷史成分股偏誤。
- 樣本外區段應只用於最終檢驗，不可依其結果反覆調參；歷史績效不保證未來獲利。
- 模擬委託、帳戶現金、持股及成交明細使用 SQLite 保存；但若資料庫位於 Streamlit Community Cloud 暫存磁碟，重啟或重新部署仍可能清除。JSON 可手動跨裝置備份／還原，沒有雲端自動同步；匯入會覆蓋目前帳本。
- 自動出場已加入 `adaptive_exit_monitor.py`：O'Neil 以 7–8% 作為初始風險參考、獲利達 20% 進入檢視並以 3 ATR 追蹤；Minervini 依結構失效價、2R 移至成本保護、3R 啟動 2.5 ATR 追蹤；ATR 動態策略使用可比較的 1.5／2／2.5／3 倍候選值。策略不設固定 10% 硬性停利，讓獲利部位依保護停損退出。所有參數仍待台股樣本外驗證。

## 官方交易日曆

模擬委託介面依市場別核對官方交易日曆：上市使用 TWSE 官方 JSON 日曆，上櫃使用 TPEx 官方「開休市日期表」頁面。兩者均快取 6 小時；官方資料無法取得、格式錯誤或缺少目標年度時，該市場的委託及撮合採 fail-closed 停止。TPEx 頁面由官方網站 HTML 表格解析，若網站改版或雲端來源遭拒絕，會停止上櫃委託而不猜測日期。臨時颱風停市等公告可能未即時反映，仍須核對當日交易所公告。

官方來源：TWSE OpenAPI `https://openapi.twse.com.tw/v1/holidaySchedule/holidaySchedule`；TWSE 日曆 `https://www.twse.com.tw/zh/trading/holiday.html`；TPEx 官方開休市日期表 `https://www.tpex.org.tw/web/bulletin/trading_date/trading_date.php?l=zh-tw`。

## 官方漲跌停價驗證

模擬委託引擎依證券市場別讀取交易所官方每日資料，不以昨收乘以 1.1 推算。上市使用 TWSE TWT84U 的本日漲停價、本日開盤競價基準、本日跌停價；上櫃使用 TPEx 官方每日行情所提供的次日參考價、次日漲停價及次日跌停價欄位。價格資料快取 60 秒；證券代號、日期或價格欄位無法核對時，拒絕委託。交易所提供無漲跌幅限制的特殊標記時，依官方標記處理；無法辨識的特殊商品不自行推算，採 fail-closed。首五日、外國成分 ETF、槓反商品及其他特殊類別仍需持續擴充分類與官方資料驗證，不能視為已完整涵蓋所有商品規則。

若使用者的電腦不能下載或安裝任何程式，可直接使用 Streamlit 網頁中的「自動交易（模擬）」分頁：

- 選擇最多 5 檔監控標的，按「立即執行一輪模擬監控」可手動執行一輪。
- 勾選「網頁開啟期間每 30 秒自動執行一輪」後，Streamlit fragment 會在目前網頁工作階段存活時定期執行。
- 自動買進模擬委託預設關閉；只有使用者明確勾選後才會建立模擬買進委託。

- 不需要在使用者電腦安裝 Docker、Python 或其他程式；依賴套件由 Streamlit Cloud 部署環境安裝。

**限制：** 此模式不是 24/7 常駐服務。關閉網頁、工作階段逾時、雲端休眠、部署重啟或網路中斷時，Worker 不會持續執行。Streamlit Community Cloud 的暫存檔案系統可能在重啟或重新部署後清除 SQLite 資料；請定期使用網頁提供的帳本備份功能。免費雲端仍有資源與使用限制，不能承諾不限使用量、永久保存或不中斷服務。若需要真正持續執行，仍需自有常開設備或有額度限制的常駐主機。

## 常駐模擬交易 Worker（Docker Compose）

本專案新增獨立的 paper_worker.py，不依賴 Streamlit 頁面是否開啟。Worker 與網頁服務透過同一個 Docker named volume 共用交易 SQLite 與歷史行情 SQLite；主機重啟後資料仍保留在該 volume。

### 啟動方式

~~~bash
cp .env.example .env
# 編輯 .env：設定 PAPER_WATCHLIST；確認資金與標的後，才將 PAPER_AUTO_ENTRIES 改為 true
docker compose up -d --build
docker compose ps
docker compose logs -f paper-worker
~~~

網頁預設位於 http://localhost:8501。Worker 每 30 秒輪詢一次，預設最多監控 30 檔；觀察清單格式為 2330:上市,6488:上櫃。持倉標的也必須放在觀察清單，Worker 才能取得市場別與報價以管理退出。

### Worker 執行規則

- 盤中使用 Yahoo Finance 1 分鐘行情；報價時間必須在 60 秒內，過期、時間錯誤或來源缺失一律不交易。
- 日線歷史優先 FinMind TaiwanStockPriceAdj，必要時才使用 Yahoo Finance 還原日線備援；只使用今日以前已完成的日線，至少 260 根才計算三種策略訊號。
- 三種策略（Minervini 趨勢模板、O'Neil CAN SLIM 技術代理、Livermore 順勢突破）以訊號共識數及 20 日動能排序；這是可稽核的規則策略，不宣稱是已驗證的機器學習超額報酬模型。
- 新進場依 NT$500 單筆風險預算，再受 NT$20,000 單筆委託、NT$25,000 單一標的、NT$80,000 總曝險、現金及交易筆數限制約束。
- 每個報價時間戳只處理一次；Worker 使用 SQLite 租約避免兩個程序同時操盤，並保存心跳、成交、錯誤與策略事件。
- 動態出場使用 PAPER_EXIT_PROFILE 與 PAPER_ATR_MULTIPLE；預設 ATR 動態策略。Worker 會在 09:00–13:30 管理持倉，買進只在一般盤 09:00–13:25 執行。
- PAPER_AUTO_ENTRIES 預設為 false。設為 true 才會建立自動買進模擬委託；不論此設定為何，Worker 都不可能送出真實券商委託。

### 環境變數

| 變數 | 用途 |
|---|---|
| PAPER_WATCHLIST | 必填觀察清單，最多 30 檔，格式如 2330:上市,6488:上櫃 |
| PAPER_AUTO_ENTRIES | 自動買進模擬委託開關，預設 false |
| PAPER_EXIT_PROFILE | atr_dynamic、oneil_growth 或 minervini_sepa |
| PAPER_ATR_MULTIPLE | ATR 移動停損倍數，預設 2.0 |
| PAPER_ETF_SYMBOLS | 以逗號分隔的 ETF 代號，使用 ETF 升降單位 |
| PAPER_WORKER_INTERVAL_SECONDS | 輪詢秒數，最少 10 秒，預設 30 秒 |
| FINMIND_TOKEN | 可選 FinMind API Token |

停止服務：docker compose down。若要連同模擬帳本資料一併刪除，才使用 docker compose down -v（此操作會刪除持久化交易資料，請勿誤用）。

### 重要限制

- Docker Compose 必須部署在持續運作且有持久化磁碟的主機（例如自行管理的 VPS）；Streamlit Community Cloud 不會因 GitHub 更新而自動啟動這個常駐 Worker。
- Yahoo Finance 1 分鐘行情可能延遲或中斷；60 秒門檻會因此跳過交易，不代表行情是交易所認證即時報價。
- 目前只掃描使用者設定的最多 30 檔，不會對全市場數千檔逐檔抓取日線，避免超過資料服務 API 配額。
- 模擬撮合仍以報價觸及限價作為成交假設，不含真實委託簿、排隊順位、部分成交與市場衝擊。
- Worker 與 Streamlit 必須使用同一組 EXECUTION_DB_PATH、MARKET_DB_PATH 及共享資料卷；若分開部署或使用不同磁碟，帳本不會自動同步。
- 自動進場是多策略技術規則，不代表已經訓練或驗證出可持續獲利的 AI 模型。需先長期模擬並檢查扣除成本後的樣本外績效。

## staged 自動交易架構（初期資金 NT$100,000）

目前專案採 staged 路線：先完成自動策略與模擬交易驗證，再評估真實券商交易。預設模擬本金為 NT$100,000；新帳戶或完全沒有委託、成交及持倉的空帳戶，會套用此設定。已有交易紀錄的帳戶不會因設定變更而覆寫資金或帳本。

- `trading_config.py`：集中管理初期資金及保守風控預設。初始單筆委託上限 NT$20,000、單一標的曝險 NT$25,000、總曝險 NT$80,000、每日已實現虧損停手 NT$2,000、最多 3 筆未完成委託、每日最多 8 筆委託、單筆風險預算 NT$500；不允許放空。這些是工程保護值，不代表可達成的報酬或最大損失保證。
- `broker_gateway.py`：定義未來券商 Adapter 介面（帳戶、下單、撤單、未完成委託及成交回報）。目前只有 `UnconfiguredBroker`，所有實盤操作都會明確拒絕，不會假裝成功。
- `trading_mode.py`：staged/live 模式閘門。即使檢查清單全數勾選，仍須提供真正標示為 live 的券商 Adapter 才能進入 LIVE；目前沒有任何實盤 Adapter。
- `adaptive_exit_monitor.py`：保存每檔持倉的初始風險、最高價、ATR 與動態保護停損；僅接受新鮮盤中報價並產生模擬退出訊號，不會直接送出券商委託。
- `tests/test_adaptive_exit_monitor.py`：驗證 ATR 移動停損、Minervini 結構失效與 R 倍數、O'Neil 獲利檢視、報價新鮮度及持倉風險狀態。

### 尚未完成、不得宣稱已自動實盤
券商尚未指定，因此目前不會登入券商帳戶或送出真實委託。已新增獨立常駐 Paper Worker，可於持久化主機持續執行模擬報價監控；Streamlit Community Cloud 本身仍不會自動啟動該 Worker。要達到真正無人值守的全自動實盤，仍需選定券商、完成官方 API Adapter、使用安全憑證管理、部署常駐 Worker／排程器、可靠持久化資料庫、即時行情來源、券商委託與成交回報同步、斷線復原及人工緊急停止演練。任何實盤啟用前都必須通過完整模擬及小額驗證。


## Windows 本機登入後自動啟動

若不打算讓電腦 24 小時開機，可使用 Windows 工作排程器在使用者登入後自動啟動 Docker Desktop、Streamlit 與 Paper Worker。完整安裝、檢查、停止及移除方式請參閱 [Windows 部署指南](windows/README_Windows.md)。電腦關機或睡眠期間不會監控行情或執行停損；此部署仍是純模擬交易。

## Walk-forward 效能與驗證

- AI 自適應 Walk-forward 預先計算 18 組候選訊號，樣本外窗口重用已計算的訊號資料。
- 候選選擇快取依精確訓練資料指紋及本金、持倉、風險、成本、出場與暖機設定識別；資料或設定不同即重新評估，快取容量有限。
- 網頁提供每個已完成樣本外窗口的進度與日期資訊；快取不跨越不同訓練資料切片，也不會將外層樣本外資料用於策略選擇。

## 多策略與投資組合風險研究

- 五種日線 OHLCV 策略：趨勢結構延續、量價突破、動能趨勢突破、長期趨勢過濾的均值回歸、波動收縮後突破。收盤形成訊號，最早於下一交易日模擬成交；新倉股數上限為訊號日已知的 20 日平均成交金額 1%，不使用當日尚未完成的成交量。
- 當前股票風險快照採共同日期收盤報酬、協方差收縮、長倉風險平價、單檔權重上限與明確保留現金；不會回填歷史樣本外績效。
- 動態策略組合使用各固定策略的樣本外資產曲線，依過去報酬估計風險並定期再平衡；每個交易日的權重只使用該日以前資料，前 60 日等權暖機。這是獨立研究曲線，不是紙上交易帳本。
